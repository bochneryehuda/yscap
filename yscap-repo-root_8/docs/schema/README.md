# The map of the PILOT database

**These files are DOCUMENTATION. Nothing in PILOT reads them at runtime, and nothing ever should.**

549 numbered migration files in `db/` build this database. That is a complete instruction set and a
useless picture: to know what `applications` looks like today you have to read all of them in order.
These files are the picture.

| File | What it is |
|---|---|
| `schema.prisma` | Every table, column and relation, in one readable file. Generated by Prisma. |
| `beyond-prisma.json` | Every object Prisma's schema language **cannot** express, plus a fingerprint of every table and column. Generated by our own code. Machine-checked. |
| `BEYOND-PRISMA.md` | The same, readable. |

## The one rule

**Never rebuild a database from these files.**

Prisma's schema language cannot represent triggers, functions, CHECK constraints, generated columns or
partial indexes. On this database that is **736 objects**. A rebuild from `schema.prisma` produces SQL
that runs **without a single error** and silently leaves out every one of them — including the guard
that refuses to sign off a budget condition unless the totals match to the cent, and the `full_name`
column the database calculates itself precisely so it can never drift.

`db/` builds the database. `docs/schema/` describes it. They are not interchangeable.

## Regenerating

Both commands **only read**. Point them at a **restored copy or a scratch database — never
production**. Better still, use a role with `SELECT` only, so "it cannot write" is a property of the
credential rather than of remembering the right command:

```sql
CREATE ROLE schema_reader LOGIN PASSWORD '…';
GRANT USAGE ON SCHEMA public TO schema_reader;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO schema_reader;
```

```bash
cd yscap-repo-root_8
export DATABASE_URL='postgres://…'      # a COPY, not production

npm run schema:snapshot                  # beyond-prisma.json + BEYOND-PRISMA.md
npm run schema:map                       # schema.prisma  (downloads Prisma on demand)
```

Then commit `docs/schema/`.

**Prisma is deliberately NOT in `package.json`.** Render's build runs `npm install`, which installs
devDependencies too, and Prisma pulls native query engines — putting a large native download into the
production build of a live lending system to serve a documentation tool. `npm run schema:map` fetches
it on demand instead, **pinned to an exact version** (`prisma@6.19.1`), because `prisma@latest` is v7
and v7 rejects the schema format v6 writes. The application's dependency list is byte-for-byte
unchanged by any of this.

## The drift check

A map nobody updates is worse than no map — it is a document people trust that has quietly stopped
being true.

```bash
npm run schema:check      # needs DATABASE_URL; self-skips without one
```

It rebuilds the inventory from the database and names every difference: which trigger appeared, which
column changed, which one is **gone**. It uses `pg`, which the app already has — a safety check that
needs a large tool downloaded before it can answer is a safety check people switch off.

**It is advisory today** — it reports and exits 0. Set `SCHEMA_SNAPSHOT_ENFORCE=1` to make it block.
That flip is deliberate and deferred: the standing rule for this work is that nothing which passes
today may start failing, so this lands announcing itself, and enforcement follows once regenerating is
a habit. No code change is needed for the flip.

## Where the snapshot came from

The committed files were generated from a database built by applying all 549 migrations to an empty
Postgres 16 — the same thing CI does on every run.

**That is not quite the same as production**, which is those migrations applied incrementally over a
year plus anything ever changed by hand. The two should be identical and nobody has ever checked.
Running `npm run schema:snapshot` against a restored production backup and diffing the result against
what is committed here answers that question at zero risk. A match is a strong statement about the
health of the migration chain; a difference is something real that nobody knew about. Either is worth
having, and it is the first thing to do when a restored copy is available.
