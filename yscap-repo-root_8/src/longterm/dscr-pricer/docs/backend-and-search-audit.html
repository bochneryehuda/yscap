01 Storage — database, never RAM

Two tiers: keep the truth for 30 days, keep the recipe forever

Each priced search produces a large raw Lender Price response (~7 MB here, more on broad searches). Storing every one forever is expensive, so we split each quote into two records written to the database at search time — never held in memory between requests.

Store the blob compressed (object storage or a blob column). Gzip takes ~7 MB down to a few hundred KB. A nightly job deletes rows past expires_at.

Why it works

The recipe is tiny, so keeping it forever is cheap and every quote stays reconstructable. The raw is what's expensive, so only recent quotes — the ones anyone actually revisits — hold it. Lender Price's request already carries a top-level date field (null = today), and its rate sheets are dated (rateValidDate, validAsOf), which is exactly what makes the after-30-day as-of re-pricing possible.

Honest caveat

An as-of re-run is close, not identical — rate sheets, adjustments and eligibility can be restated after the fact. That's the whole reason we keep the real raw for 30 days: within the window it's the exact truth, no re-run needed. A reconstructed result should be labeled as such.

03 Coverage

Every gap is now closed

The 17-search recording closed every remaining gap. Condo (Condos), non-warrantable, all three borrower types, every prepay term including no-prepay, and the interest-only / escrow-waive / first-time-homebuyer effects are all confirmed and wired.

Nothing left

No more recordings are needed to build the search. Every field and token in the pricer is now confirmed against a real capture — the payload preview shows "✓ all field tokens confirmed." Next step is entirely on the result side: which lenders/programs to display, white-labeling, and what to show vs. hide.
